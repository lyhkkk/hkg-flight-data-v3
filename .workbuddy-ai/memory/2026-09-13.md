## 时间锚点（step 1）：进入/刷新时停在当前 HKT 航班

**需求**：TUI 和 web 刚进去或刚刷新时，离港/到达都显示当前 HKT 的航班；
用户可自行向前/向后翻页。用户已批准的设计：**锚点滚动**（不是时间窗过滤，
不隐藏数据、不改搜索/筛选语义）、**接管后固定**（首次手动移动即脱离时钟）、
**步长 = 一屏航班**、跨 24:00 沿用既有 `_search_dates` 三条规则。

**分两步**。本次只做 step 1（锚点滚动 + 今日数据）。step 2（poller 跨日窗口、
`retain_dates`、`api_flights` 窗口默认值）**尚未开工**。

### 挖出并修掉的真 bug：`anchor_step` 实际只前进 1 行

初版按「步进 **selection**」写：

```python
_select_index(state, rows, page.selected_index + delta, capacity)
page.anchor_minutes = row_minutes(rows[page.offset]["record"])
```

`_select_index` 的 height 语义是「把选中的行留在视窗内」，于是
`index = O + capacity` 时算出 `offset = index - height + 1 = O + 1`。
实测（capacity=20）：`offset 0 → 1 → 21 → 41`，**第一步只前进 1 行**，
与上一屏重叠 19 行。改成步进 **offset**：

```python
_park_index(state, rows, page.offset + delta)
```

复测 `0 → 20 → 40 → 60`，连续无重叠。

### 新踩的坑

1. **`_window` 会把 offset 回拉到 `len(rows) - capacity`**，所以**最后一屏是满的、
   会和上一屏重叠**。测试里断言"上一屏的行绝不出现在本屏"在尾部必然失败。
   要断言连续性，样本必须足够大（`make_combined_snapshot(400)`）。
   这是刻意行为，已单独用一条测试锁住（`test_the_last_screen_is_full_rather_than_a_stub`）。
2. **夹具的 `flight_number` 不唯一**（`make_flights` 会注入同向重复段），
   不能用航班号判断"某行是否在屏上"。改用 `views.flight_row(...)` 渲染出该行的
   文本再比 —— 时间不同，重复段的渲染结果也不同。
3. **`views.flight_row()` 返回的是行列表**（紧凑档两行），不是字符串，比较前要 join。
4. **`visible_rows(snapshot, ...)` 要的是 flights 快照，不是 combined 快照**
   （`views._rows_for` 内部做 `snap["flights"]`）。传错就静默拿到空列表。
5. **web 端 `fitPanel` 必须算边框**：`max-height` 是 border-box，`clientHeight`
   是 content-box，差 2px 正好卡在整行边界上（capacity 从 12 掉到 11）。
   `offsetHeight - clientHeight` 就是边框；再配 `+1e-6` 防浮点抖动。
6. **`--dump-dom` 与 `--screenshot` 的视口高度不同**（`--window-size=1240,900`
   → 截图按 900、dump 按 808）。两种模式量出来的布局**不可互相比较**；
   我一度以为面板高度算错了，实际是拿 808 视口的快照去比 900 视口的像素。
7. **`--window-size` 在页面 load 之后才生效**，页面的 `resize` 监听那时才触发；
   加载瞬间取到的几何是旧视口的。
8. **虚拟时间下程序化改 `scrollTop` 不派发 `scroll` 事件**（实测收到 0 次）。
   验证滚动监听要自己 `dispatchEvent(new Event("scroll"))`。
9. **诊断块别往 body 里追加 `<pre>`**：长行会带出横向滚动条、改变布局。
   改写进 `document.title`，用 `--dump-dom | grep -o '<title>DIAG[^<]*'` 读。

## step 2：跨日窗口 —— 以及它暴露的锚点缺陷

step 2 做完才发现 **step 1 的锚点本身是错的**，这是本次最值钱的部分。

### 窗口规则搬进 `utils.board_dates`

原 `cli._search_dates` 里的三条规则升级成共用函数，`cli._search_dates` 直接委托。
**看板与搜索不可能各算各的**（有测试扫 24 小时断言 `_search_dates(None, t) == board_dates(t)`）。
窗口由**一次**读钟算出：再读一次可能跨过 23:59:59，把今天的窗口标成明天的。

- `poller`：`clock` 可注入（返回**时刻**不是分钟），`_refresh` 用 `board_dates(now)` 逐日抓取并 merge。
- 发布 `records_date`（看板自己的钟面日期）与 `records_dates`（实际窗口）**两个**字段。
- `alerts.retain_dates(dates)` 取代 `retain_date(date)`；基线剪枝用
  `pair[0].split("_", 1)[0]` 取 key 里的日期，**不能用 `startswith`**
  （`2026-09-1` 会前缀匹配上 `2026-09-11`）。

### 锚点缺陷：只看时刻会停在昨天

两天看板上 `01:30` 有两条。**先量后改**（`R:/Temp/probe_crossday.py`）：

| 输入 | 修复前落到 |
|---|---|
| `anchor_index(rows, 90)`（01:30） | index 0 = **昨天** 01:30 |
| `anchor_index(rows, 8*60)`（08:00） | 昨天 08:00 |

整个 **22:00–01:59 档**都是错的。修复：锚点升级为 `(服务日期, 时刻)`，
`anchor_index(rows, minutes, date=None)` 比较元组；不带 `date` 退化为纯时刻
（单日看板行为不变，有测试锁）。**行不带日期时视为属于正在锚定的那一天。**
贯穿改动：`presenter` → `state.PageState.anchor_date` → `session._moment()/_anchor()` →
`views.anchor_label(page, day)` → `web.py` 的 `rowDate`/`clockKey`/`anchorIndex`。

### 顺带挖出：plain 表头/页标题根本不看宽度

`plain.render_block` 第一行（`HKG | Data date …`）和页标题行**没有宽度约束**——
渲染层里仅剩的两个违反「任何渲染行 ≤ 请求宽度」的地方。**先量**
（`R:/Temp/probe_plain_width.py`）：45 列溢出 6 格，30 列 31 格，长错误串最多溢出 **55 格**。
修复：新增 `views.plain_header_line(snap, width)`（宽度归 views 所有），页标题走 `truncate`。
反证：先写测试跑挂（`AttributeError` + `48 > 45`）再改代码；修完探针 0 条超宽。

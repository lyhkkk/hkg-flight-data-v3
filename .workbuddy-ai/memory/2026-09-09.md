## 审核 TUI-IMPROVEMENT-PLAN.html（只读评审，未改任何项目文件）

对照 `hkg_flight/tui.py`、`poller.py`、`test_hkg_flight.py`、README/SPEC 逐条核实报告论断，结论：

- 报告方向正确（脏矩形式刷新、非阻塞模式、宽度适配），但有 3 处**定性过轻**、多项**遗漏**、若干**方案悬空**。

关键事实（代码级，供后续实施参考）：
1. `cmd_alerts/cmd_airlines` 内的 `stdscr.getch()` 受 `timeout(1000)` 影响 → 页面**最多显示 1 秒自动退回**离港页，不只是"按任意键返回"。
2. `CursesTUI.today_records` 在 `load_view()` 时拿到的是 poller 列表的**旧引用**；poller 用 `self.today_records = new_records` 重新绑定 → curses TUI **数据永不更新**（不是"刷新不及时"）。`poller.last_update` 目前无人读取。
3. `handle_key` 中 `1/2/5/6/W` 先于可打印字符分支 → 含这些字符的航班号（CX261、HX535）**根本无法输入**。属功能阻塞，应 P1 而非 P2。
4. curses 的 `_render_flights` **完全不显示 filter_text**（simple TUI 会打印），用户盲打。
5. `_render_airlines` 每次渲染都调 `api.fetch_airlines()`（缓存失效时走网络）；`visible_flights()` 在 `today_records` 为空时每次渲染触发 `load_view()` 同步请求 → 卡 UI。
6. `cmd_search()` / `prompt()` 是**死代码**，从未被 handle_key 调用。
7. `Poller` 没有区分数据来源的字段（只有 log），报告要求显示 "Cached data" 需要先加 `last_source`。
8. SPEC.md:175/191 仍在写 ↑/↓ 滚动，README 已修正 —— 文档修复不完整。SPEC.md:163 的 `[1]Search [2]ByDate [3]Dept [4]Arr` 与代码 `1=Dept 2=Arr` 冲突，改进报告未提及。
9. 报告内部 Esc 语义冲突：P1 导航说"返回上一模式"，P2 搜索说"清除筛选"。
10. 报告建议"REG 放入详情视图"，但 TUI 无详情视图；且未给出 40/60 列的具体降级断点。

## 追加：评审 TUI-REBUILD-REPORT.html（Textual 重建提案）

核对 15 项断言后**全部属实**（tui.py 593 行、`_render_airlines` 渲染中请求、TUI 持有旧列表引用、poller 启动双刷、限速无锁、key 跨方向撞键、CI 3.7/3.11/3.13 等）。报告事实层面可靠。

本轮新发现的三条更硬证据（原报告未列）：
1. `cli.py` TUI 路径**从未调用 `poller.stop()` / `web_server.stop()`**，也没有 try/finally —— 按 W 开 Web 后按 Q 退出，端口仍被 daemon 占用。
2. `poller.refresh_today()` 行 103-110 的告警比对段**在 `self._lock` 之外**读 `today_records`，与 UI 线程 `get_today()` 真实竞态。
3. `cli.py:_merge_fvm_data()` 是**死代码**（无调用点），所以旧 TUI 的 REG 列恒为 `-`；新 UI 首版建议干脆不显示 REG 列。

主要分歧与六问：
- **缺"先止血"档**：三个最痛缺陷（渲染中 fetch_airlines / 不重读快照 / 无 finally 清理）在现有 curses 里 0.5–1 人日可修，且产出（snapshot()、version、统一清理）正是新架构地基，不浪费。
- Q1 Textual 是否最终进默认安装（G0 就要答，不能留 G4）；Q2 3.7 `compileall` 会扫到 `hkg_flight/terminal/*.py` 与"新源码尽量可解析"直接冲突；Q3 告警未读数派生方式空白（new_flag 是消费型，建议只读版本计数器）；Q4 Esc 四层回退与平级主页模型冲突，建议砍掉"返回前一主页面"；Q5 A6 尺寸快照在 Windows 会 flaky，需按平台拆分断言；Q6 `today_str()` 用本地日期，港外用户常态拿到"明天"数据。
- 两处内部冲突：`cache_saved_at` vs "不改缓存格式"（建议取 mtime）；`--port`/`--no-poll` 只定义在 tui 子解析器上，裸入口是**新增**不是"保持含义"。

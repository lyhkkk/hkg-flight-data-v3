01 决策摘要：修复既有成果，不再重写一遍

问题不是“Textual 路线失败”，而是当前实现的关键不变量、真实交互与完成证据没有闭合；V3 的目标是让这套已经存在的工作台变得可信、可操作、可验收。

保留

可选 Textual / 标准库 plain 分层、Session + State + Presenter 骨架、四页入口、缓存 mtime、告警 revision、依赖懒加载及有价值的回归测试。

修复

快照所有权、实体连续性、刷新串行化、日期发布门、健康语义、文本安全、真实视口、焦点和后台关闭。

补证

修复前红灯、真实 Adapter、完整装配、wheel 隔离、跨平台执行、真实终端与 30 分钟采样，而不是再增加一批只测 reducer 的绿灯。

当前结论：不能沿用“G0–G4 全完成 / fully implemented”的判断；已有代码应作为待修复候选保留。候选实现是就绪度描述，不是 Agent Note 的新 Status 值。

本次授权与实施边界

用户已同意将 Python 运行时与自动化测试前置门纳入 V3 计划。实施仍必须按 V3-G0-P→G5 顺序执行；不得将“自主完成”理解为绕过停止门槛、人工终端验证或支持边界审批。G0-P 为 PARTIAL 时，仅可继续有直接证据路径的自动化阶段，不能据此作最终完成声明。

为什么不选择其他路线

  • 全部重新生成：会丢失现有有用结构，且不能消除测试层级选错这一根因，不采用。
  • 仅补几个 UI 补丁：不能解决快照污染、并发与迟到发布，无法通过核心验收，不采用。
  • 切回全新 curses 内核：只有用户改为要求“Python 3.7 + 零依赖全功能”时才重新评估；本轮不恢复已删除的旧 TUI。
  • 原地修复 + 分阶段证据：与当前投入、兼容边界和用户目标最匹配，推荐采用；若核心数据模型无法局部修复，应先提交具体替代决策而非擅自扩展重写。

03 范围、兼容边界与相对 Rev 2 的明确决策

规格归属：本报告是 V3 待批准修复规格的详细正文；唯一架构 note 记录问题、选择和生命周期并链接这里，反馈日志只登记诉求。Rev 2 保留为原批准基准，本报告继承其产品范围并明确补强失败面；不能把本报告的未来要求写成当前运行事实。
事项V3 推荐决定与 Rev 2 / 当前候选的关系
运行时支持基础 CLI/Web/plain：Python 3.7+、无必装第三方运行依赖；增强 Textual 项目支持目标：Python 3.11/3.13，最低 3.11。Python 3.14 可作为额外辅助 lane，但不自动纳入正式支持矩阵。沿用 Rev 2，不因 Textual 自身允许 3.9 就静默把项目支持改成 3.9+；修复 extra marker、selector、文档与测试的一致性。
后端选择auto 只检测运行时、依赖及 stdin/stdout TTY，绝不安装；不足则明确提示并选 plain；显式 textual 不满足条件则可诊断地失败。3.7–3.10 即使手工安装 Textual，也不属于增强支持范围；3.12 或其他版本只可写未验证，不虚报完整矩阵。
刷新返回值保持 accepted / already_running / closed 三值；already_running 定义为 pending 或 refreshing 已占有刷新槽。是对重复状态的明确细化；本轮不新增 already_pending，不让调用者凭空适配第四个值。
最小尺寸40×16 为需证明的候选支持底线；不足时显示可退出的尺寸提示并保留状态。不允许 executor 以修复困难自行提升门槛；如 40 列无法满足可读性，提交测量与建议，获用户批准后才调整支持范围。
按键权威建立一份轻量动作/上下文清单作为帮助、页脚和测试的共同来源或机械一致性检查依据。新增防漂移要求；不要求通用注册框架，纯数据表或简单检查即可；真正 Widget 焦点仍由 Adapter 验证。
证据扩展保留 A1–A11 原意并增加 A12 性能、A13 真终端、A14 按键到 Adapter 对齐。新增完成门槛，不重编号原验收；原 G0–G4 不能自动抵扣 V3-G0–G5。
就绪度与豁免未验证不能当通过；非核心平台缺口可提交缩小支持范围申请。仅用户批准后写明不支持边界；核心数据、安全、关闭与已宣传功能缺陷不能用“已知限制”绕过。

必须保持的业务契约

  • HKIA API 业务含义、现有 CLI 搜索与 --codeshare 语义、Web HTTP 契约、缓存/告警在盘格式、告警生成与清除规则不变。
  • 告警徽标表示 active count + alerts_revision，不引入 unread、确认/消费标志或跨重启恢复。
  • cache_saved_at 来自本地文件 mtime，不是 HKIA 生成时间，也不是最后 API 成功时间；可取得就不写 UNKNOWN。
  • 当前 today_str() 使用系统本地日期；本轮注入时钟测试现行日期语义，不顺便在一个模块改成香港日期。全局香港业务日期统一须另行批准。
  • 全局 --cache-dir/--force 与子命令参数位置维持准确；裸入口不新增 --port/--no-poll，这两项仍属于 tui；已有 CLI/Web 回归不能为了 TUI 通过而删除。

明确不做

REG/FVM、新数据源、历史日期界面、收藏/偏好持久化、任意列排序器、Web 重写、通用事件总线、插件系统、DI 容器；不恢复旧 curses/simple，不自动提交、推送、清库、reset 或覆盖他人的改动。

REPAIR SPEC / 05

05 数据核心不变量 I1–I6：让测试能推翻错误实现

I1 · 所有公开读都拥有独立数据

snapshot()、today_records、get_today() 及 Session 组合快照不得泄露内部嵌套 dict/list。选择深复制或真正不可变结构均可；tuple 外壳不是深不可变。调用方持有旧快照时，后台发布也不能改变其内容。

反例：使用非空、含嵌套列表/字典的合法记录，分别修改 gate、共享号/嵌套值、append/remove，并再读所有公开出口；内部内容、revision 和之前读取的快照保持预期。空列表 append 测试只能作为补充。

I2 · 实体连续性 ≠ 内容指纹 ≠ 重复航段消歧

先调查上游是否提供稳定实体 ID；若没有，以 (date, type, normalized primary flight) 建稳定组，再以会话内稳定 token 和保守匹配维持连续性。gate/stand/belt/terminal/status 等更新只改变内容指纹，不得单独重新定义实体。计划时间/路线能否用于消歧必须依据实际样本，不能简单把所有字段拼入 ID。

匹配同组的旧/新记录时先利用可靠稳定特征，再匹配无歧义连续项；重复段仅改变可变字段和排序时仍保留各自身份。完全不可区分时保留 token 的确定性分配；若无法证明对应关系，应明确提示歧义并安全降级，不能静默把详情附到另一航班。消失时选原索引邻近项，空集清选中；详情目标同步更新或明确关闭/标记消失。

反例：同一航班 Scheduled→Boarding、gate/stand/belt 改变；两条同组航段交换顺序且一条更新；codeshare 显示变化；真正删除；跨页与筛选后重现；验证 selected_id、详情内容和可见位置，而不只是列表行数。

I3 · 所有刷新入口只有一个执行 owner

IDLE ──request──→ PENDING ──worker take──→ REFRESHING ──finally──→ IDLE
                    │                         │
                    └─duplicate: already_running (coalesced, no extra fetch)
IDLE / PENDING / REFRESHING ──close──→ CLOSING ──cleanup result──→ CLOSED

推荐固定延迟调度：初次恰好一次；一次完成后计算 next_refresh_at；MANUAL/no-poll 不设自动到期。refreshing 中的重复手动/定时请求合并到当前工作，不累积逐次队列；若跨日检测需要新日刷新，只保留一个明确的新代次需求。异常、空成功、缓存回退都在 finally 复位内部与公开状态并通知等待者，避免永久 already_running。

start()、start_background()、request_refresh()、refresh_today() 和定时路径必须进入同一协调器；兼容同步入口可提交并等待同一任务结果，不能直呼独立抓取函数。保留实际调用方依赖的返回形状与等待行为，G0 先列清；关闭后所有入口拒绝新工作。

反例：用 barrier/Event 同时启动真实公开入口并阻塞 fetch，统计 max_in_flight == 1；首刷完成→再次手动刷新确实可成功；pending 第二次返回 already_running；成功/异常后内部不挂死；no-poll 受控推进多个周期仍恰好一次，手动一次后计数变二。不能仅检查 request_refresh 返回值或最终总次数。

I4 · 日期 + generation + closing 在发布点再次校验

请求携带 requested_date 与 generation；成功、失败与缓存回退发布前均校验当前有效代次、当前业务日期和关闭状态。失效结果不得覆盖记录、把旧日成功时间算成今日成功、生成/清除不应出现的告警、唤醒已退出 UI。运行中检测跨日要失效旧请求并排入新日请求，但仍满足 I3 单一执行。

新日未拿到数据时可保留明确标记 previous day 的旧快照，不能篡改 records_date；今日失败和旧日成功可并存。API 已有按请求日期写缓存的行为需梳理：本轮不承诺强制杀死正在进行的网络/文件写入，但不得把旧响应写成今日文件或从缓存旁路重新发布；持久化格式不变。

反例：固定 23:59 → 00:00，阻塞旧日请求后再放行，断言无旧日有效发布与告警副作用；对隔离发布 seam 注入新→旧逆序完成，旧结果被拒绝。后一个测试模拟迟到/重复事件，不通过同时运行两个生产 fetch 破坏 I3。

I5 · Session 拥有资源，也拥有关闭失败结果

保存 Poller/航司 worker/Web 启停任务和定时器订阅的所有权；航司失败重试可达，并复用自己的去重/关闭门。进入 closing 即拒绝 refresh、Web toggle、metadata retry；关闭通知与延迟发布有一致门。close 幂等，共享一个关闭过程并保留首次/最终逐项结果，不能第一次超时第二次就回报全成功。

UI 退出请求先阻止交互与订阅，再退出框架恢复终端，慢等待放在框架恢复之后或专用关闭任务，禁止 UI action 同步等待 Poller.join / Web.shutdown。使用明确总预算（初拟 20 秒）而非每个资源各等 20 秒；daemon 存活不等于已经清理。q、Ctrl+Q、Ctrl+C、EOF、初始化部分失败和框架异常均走统一协议。

反例：阻塞航班与航司 fetch/Web start，关闭后再 release，快照/告警/UI revision 不再被改写；重复 close 不掩盖未结束资源；端口占用不显示 ON；退出时终端先恢复。无法取消的同步 I/O 只允许在有界等待中收尾，超时写入明确失败记录。

I6 · 健康状态四维正交

维度 / 字段契约必须覆盖的组合
modeAUTO / MANUAL，只表示调度方式。MANUAL + CACHE + ERROR + STALE 不能被简单显示成“Manual”而隐藏错误。
sourceAPI / CACHE / MEMORY / NONE，只说明正在展示的数据来自哪里。API 失败仍有 usable cache：source=CACHE 且保留 api_failed。
outcome / loading未尝试、加载中、成功、失败分开；loading 不覆盖前次结果。[] 是成功空数据；None 是失败；无数据的失败和无航班的成功有不同空态与退出码。
freshnessFRESH / STALE / UNKNOWN，由明确时间依据与阈值计算；阈值在 G0 与调度间隔一起确认并测试临界值。有 mtime 的旧缓存 STALE；未知时间 UNKNOWN；last_api_success_at 缺失不可猜 API OK。
timestamps / revision保留 requested_date、records_date、last attempt / success、cache_saved_at、next_refresh_at；对可见健康变化推进 revision。失败无新记录仍能被 UI 看见；关闭/旧代次不推进当前成功时间。

06 呈现不变量 I7–I9：文本安全与实际终端几何

I7 · 所有外部文本都是字面文本

API、缓存、用户输入和错误信息均不可信。增强 renderer 使用 Rich Text / style span 或关闭 markup 的 Widget；状态着色是内部枚举到样式的映射，不将外部 status 拼入 [color]...[/color]。plain 与增强共用标准库可用的控制字符清洗策略。

建议单行字段将 LF/CR/TAB 变为空格，ESC、C0/C1、DEL 等转换为可见安全标记或移除；详情只保留 renderer 自己插入的换行，不允许输入控制屏幕或伪造行。策略需在实现与测试中固定，原缓存/业务值不因此重写。常见 CJK/组合字符保留；双向控制等无法安全呈现的格式字符采用明确规则处理，不能一刀切损坏普通组合文本。

反例：[bold red]INJECT[/]、字面方括号、ESC 清屏/OSC 链接、CR、TAB、换行、C0/C1、长中英文、组合重音；同时覆盖表格、详情、帮助内的用户词、日志和 plain 捕获输出。断言无原始终端控制，不将字面标签解析成样式，清洗不会抛错。仅“自己没加 ANSI”不构成安全保证。

I8 · 宽度按 display cell，不按 len()

共享可测试的测量/截断/填充契约，标准库实现可以覆盖基础 CJK、组合字符和控制码；增强可使用其依赖的等价 cell 测量能力，但基础包不能反向要求 Rich/Textual。截断不能拆坏组合字符簇或输出未闭合的样式片段，省略号也占宽度。East Asian Ambiguous、emoji/ZWJ 在不同终端可能有差异：先列 supported fixtures，再在 A13 记录终端边界，不能宣称全部 Unicode 无条件完美。

I9 · 可见记录数由真实内容区域导出

body_width  = Widget.content_region.width  (扣除 padding / border / scrollbar)
body_height = Widget.content_region.height
usable_rows = max(0, body_height - table_header_rows - fixed_overlay_rows)
capacity    = floor(usable_rows / row_height)  # compact: row_height = 2
0 capacity  ⇒ size hint / no navigation division-by-zero
selection / offset / PgUp / PgDn / Home / End / slicing 共用 capacity

不能把屏幕 size 当 body size，也不能计算出 capacity 后再额外加两行表头。宽模式列表与详情各有预算；窄模式全屏详情应可滚动并让长字段最终可读，不能只取前 available 行。搜索 Input 的边框/焦点样式必须算入实际高度。

反例：在 40×16、60×20、80×24、120×30、160×40 以及 30×8 逐页渲染、逐次 resize、下移到末项/上移/翻页；断言 display-cell 宽与总 body 高均不越界，选中项实际位于可视区域而非仅存在于未显示字符串中；两行紧凑布局一页容量正确。告警宽屏详情不能访问航司专用 code 字段。

保留 HKG OPS 的视觉方向

航班号/时间/状态为主信息，路线与 gate/stand/belt 随尺寸渐进显示；header 分清数据日期与显示时钟，nav 保持四页清晰，search/filter 显式显示作用域，footer 只提示当前可用动作。状态不只靠颜色；NO_COLOR 在主题、样式和 plain 全路径验证。网络日志不能直接穿透全屏 stdout/stderr：会话级日志投递到安全状态区或退出后的诊断，队列有界，CLI 原日志仍可用。

性能测量协议

  • 记录硬件、OS、Python、框架/终端版本、数据量、刷新间隔与采样脚本；离线首屏从入口启动到可交互 shell，不以 API 完成为条件。
  • 在 1,000/100/100 夹具下对导航、切页、筛选、输入反馈至少收集 100 个样本，报告 p50/p95/max；搜索防抖约 150ms 单列，不能偷偷扣掉其他耗时；快照发布到可见另测至少 100 次。
  • 持续 30 分钟，0 分钟起每 5 分钟记录 widget 数、活线程、通知/命令队列长度、进程内存及工作量；区分初期缓存预热与持续线性增长，若只保留最新版本则队列应有明确上限。
  • 退出同时记录框架恢复时间与资源最终退出时间；HTTP 15s timeout、限速等待与正在启动的 Web 都纳入总预算。超预算不可报成功；需要改变预算时提供测量并获得批准。
  • 刷新轮询只读轻量版本 token；相同版本不重复深拷贝/整表重建；时钟标签允许轻量更新。用调用次数/采样证据证明，不凭代码意图断言性能。

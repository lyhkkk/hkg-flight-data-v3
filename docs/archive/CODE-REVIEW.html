二、新引入 / 修复不彻底（6 项）

N1. _validate_date 被复制了三份 NEW 简洁

api.py:19 · cache.py:27 · web.py:17

同一个正则校验函数在三个模块各写了一遍。现在改校验规则要动三个地方，正是上一轮"两份实现分叉"的缩小版重演。

建议：下沉到 utils.py 定义一份 validate_date()，三处 import 复用。顺带把 _safe_cache_path 也一并放过去。

N2. Python 侧 _esc() 定义但从未使用 NEW 死代码

web.py:24-26

转义实际由前端 JS 的 esc() 完成，这个 Python 函数没有任何调用点。留着会让人误以为服务端也做了过滤，是安全隐患式的误导。

建议：删除；或保留并在 api_*() 返回前对字段做一次服务端净化（纵深防御更稳）。

N3. shutil 成为死导入 NEW

cli.py:176

改用 os.remove 逐文件删除后，import shutil 留在原地没删。同时 cli.py 仍有 9 处未使用导入（API_BASE, DEFAULT_MIN_API_INTERVAL, filter_records, format_time, get_status_info, make_flight_key, status_pair, threading）。

N4. 参数错误返回 HTTP 200 NEW API 语义

web.py:174-175, 214-215
if not _validate_date(date_str):
    return {"error": "Invalid date format. Use YYYY-MM-DD"}   # 但仍以 200 返回

前端 allFlights = await res.json() 拿到的是一个 dict，随后 flights.filter(...) 会抛 TypeError，页面静默白屏。路由级 404 已经用对了 _send_error(404, ...)，这里却没用上。

建议：让 api_flights/api_search 抛参数异常，由 handler 统一返回 400；前端加 Array.isArray(res) 校验。

N5. COMMANDS.md 记载了一条跑不通的命令 NEW 文档

COMMANDS.md:119 — python -m hkg_flight web --force

--force / --cache-dir 是全局选项，必须写在子命令之前。文档里这条会直接报错退出：

$ python -m hkg_flight web --force
hkg_flight: error: unrecognized arguments: --force      # exit 2
$ python -m hkg_flight --force web                      # 正确
建议：把文档改成 --force web；或者更省事——给 web 子命令也加一个 --force，两种顺序都能用（argparse 支持在父子解析器上同名 dest）。

N6. --force 语义仍然过重 NEW 体验

cli.py:417-419 → clear_cache(confirm=True)

原建议是"绕过本次缓存"，现在实现仍是清空整个缓存目录，且 confirm=True 跳过确认。后果：--force query CX759 会连带删掉 alerts.json（告警历史）和 airlines.json（24h 缓存）。

建议：让 APIClient 支持 bypass_cache 标志（本次请求直连 API 不读缓存），--force 只切换该标志，不动磁盘。

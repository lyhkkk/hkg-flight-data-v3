01整体决策：前端重建，业务保留

我建议新 TUI 不再继续修补 curses，而是采用 Textual 作为唯一的完整交互界面；保留标准库 CLI/Web 和一个诚实、简单的文本降级入口。

这不是无代价的替换。推荐方案需要你批准“新 TUI 允许第三方可选依赖，运行环境提升为 Python 3.11+”；基础包仍保持 Python 3.7+ 契约。如果必须坚持所有界面零依赖且支持 3.7，应改选“新状态内核 + curses 渲染器”，而不是悄悄放宽原项目承诺。

用户得到什么

  • 启动先看到界面，不再等网络请求结束。
  • 离港、到达、告警、航司都是可长期停留的页面。
  • 搜索输入不会被数字、W、Q 快捷键吞掉。
  • 选中航班后看完整详情，刷新不会无故跳回首行。
  • 明确知道数据日期、来源、更新时间和失败原因范围。

维护者得到什么

  • 界面只读快照，不在渲染函数里请求网络。
  • 数据、交互、呈现各有明确所有者。
  • 核心行为可以脱离真实 API、真实终端测试。
  • 不再维护两套全功能 TUI，也不引入泛用插件系统。
  • 允许渐进替换，但旧实现有明确退场条件。

真实可选路线

B · 从零实现 curses + 状态模型守住标准库与 Python 3.7；复用已有终端技能焦点、输入法、弹窗、宽字符、布局及跨平台能力仍需自己承担若零依赖是硬约束，选择此路线
C · Textual 可选主界面借助成熟终端框架组织布局、输入和可测试交互新增依赖、运行时分层、打包矩阵；框架升级需要管理推荐，但以兼容性验证为准
D · Web / 桌面界面替代 TUI图形表现空间更大改变终端使用方式，且项目已有 Web；另开产品战线不属于本次范围

Textual 是候选技术决策，不是“已经安装并验证”的事实；本轮没有查询其最新版本，也不虚构最低支持版本或具体框架方法。阶段 G0 必须查阅当时的官方文档与发行元数据，选择并实际验证依赖范围。

↑ / ↓、PgUp / PgDn逐行选择、按当前视口翻动；左右键作为旧翻页兼容别名，仅列表焦点有效服从输入框自身编辑行为
Home / End当前结果集首条 / 末条输入框行首 / 行尾
Tab / Shift+Tab在实际可交互区域间轮转；焦点可见正常焦点轮转；输入不会被悄悄提交成其他动作
f / r / w / ? / q筛选面板 / 刷新 / Web 开关 / 帮助 / 退出，字母大小写等价普通文本；不能误启动 Web 或退出
Ctrl+Q / Ctrl+C全局退出并统一清理同样有效；这是输入态的明确退出入口
不要继续承诺“Q 在所有输入情境退出”。它与“能搜索包含 Q 的航班号”矛盾；新契约是 Q 在浏览态退出，输入态用 Ctrl+Q / Ctrl+C。帮助、底栏与测试必须同一口径。

搜索与状态保留

  • 航班搜索：仅匹配显式白名单字段——主航班号、代码共享号、航司代码、起讫机场代码、gate、stand、terminal、状态文本；大小写不敏感、空白分词、词之间 AND、每词字段之间 OR；航班号字段另做去空格规范化，使 CX 759 可匹配 CX759；不再对整个 dict 做字符串搜索。
  • 代码共享：默认纳入匹配；详情显示匹配的共享号和主航班号，避免“搜 CX 却显示另一航司”无解释；不修改现有 CLI 的 --codeshare 语义。
  • 航司页：按 code/name 搜索；航司筛选匹配 airline_code 与主航班号前缀，代码共享是否纳入由显式开关控制，默认关闭。
  • 告警页：按航班、变化字段、前后值和状态搜索；同时间告警使用确定性次级排序；找不到当前航班时展示告警自身快照，不伪造详情。
  • 默认顺序：航班沿用计划时间顺序；告警按 raised_at 倒序；航司按代码排序。首版不增加任意列排序编辑器。
  • 每页独立保存：搜索词、结构化筛选、选中航班、视口偏移和进入详情前焦点。刷新保留选中项；项目消失时选择原位置的邻近条目并提示；筛选变化重新校正索引。
  • 即时搜索：约 150 ms 防抖作为目标，只在内存中筛选，输入一个字符绝不能触发一次 API 请求。

关键接口与不变量

接口（概念契约，非现有方法）调用者只需知道内部负责隐藏
snapshot()无网络、原子返回记录与版本、日期、来源、健康状态；返回值不会被后台修改锁、缓存回退、记录与元数据一致性；深拷贝或真正不可变结构，不能只 tuple 包住可变 dict
request_refresh()立即返回 accepted / already_running / closed；完成通过新版本快照通知定时/手动请求合并、限速、错误捕获、单次在途刷新
dispatch(action)更新会话内 UI 状态，产出新投影与必要命令焦点、返回顺序、筛选、选中保留；自身不做网络 I/O
close()幂等；禁止新命令，关闭本会话拥有的资源，返回清理结果停止定时器、屏蔽迟到消息、Web 停止、worker 退出与超时记录

行身份：首选 UI 专用 (date, type, flight_number)，不能只用行号，也不能假定现有 key = date + flight_number 在跨方向列表一定唯一；真实样本若出现同日同方向重复航段，G0 需明确扩展字段并加夹具，不修改缓存/告警键格式来掩盖问题。

07数据可靠性：不再把“看起来新”当作“真的新”

快照需要携带的信息

revision、records_date、records、source(api/cache/memory/none)、last_attempt_at、last_api_success_at、cache_saved_at、last_error、refreshing、polling_enabled、next_refresh_at；告警与航司各有版本/加载状态。请求失败也必须推进健康版本，即使航班内容完全没变。

场景展示与行为禁止的误导
首次加载先显示空壳与 Loading，再后台获取；缓存可用则显示 CACHE 和原始存储时间不把 0 条等同于失败，不在 UI 线程等 15 秒
API 成功展示 API 成功时间；返回 [] 也属于有效成功，更新为空结果不使用列表 truthiness 判断成功
API 失败、有同日内存保留最后成功内容，显示 MEMORY / ERROR，API 成功时间不前移不静默清空列表，不伪造刚刚成功
API 失败、仅缓存可用展示 CACHE、cache_saved_at、请求失败状态；缓存年龄未知则明确 UNKNOWN AGE读缓存的时刻不是数据生成时刻
失败且无可用数据“无法获取数据，未找到可用缓存；r 重试”，导航、帮助和退出仍工作不显示“没有航班”来掩盖失败
搜索无结果显示当前条件与清除入口；保留原始总数不触发额外刷新或把未筛选的到达/离港混入
航司加载失败单独标记航司错误；其他页面继续可用；失败/空列表要通过新增元数据区分现有 fetch_airlines 返回 [] 本身不足以证明失败原因
Web 端口占用状态为 ERROR，显示实际端口与启动失败；可重试或继续看航班不只看按键已触发就显示 ON
  • 过期规则：自动轮询开启时，距最新已知 API 成功或缓存保存时间超过 max(2 × poll_interval, 60s) 标记 STALE；时间未知显示 FRESHNESS UNKNOWN。请求失败单独标记 ERROR，不等待过期阈值；关闭轮询显示 MANUAL 与数据年龄，不宣称实时。
  • 日期/时区：首版保持现有 today_str 的系统本地日期语义，界面明确显示数据日期及时间偏移，不擅自称其为香港时间。跨本地午夜切换日期：旧数据要么暂时标明“昨日数据”，要么显示新日 Loading，不能换了标题仍把旧数据说成今日；旧日期迟到结果不得覆盖新日结果。统一全项目到 Asia/Hong_Kong 应另行评审。
  • 一次启动，一条轮询链：默认入口与 tui 入口统一由 Session 管理；为 Poller 增加保持旧默认行为的非阻塞启动方式供新 TUI 使用，首刷只触发一次；新 TUI 不再先同步 poller.start 再自己 fetch。
  • --no-poll：只关闭定时刷新；仍后台首刷一次，r 可主动刷新；不得顺手开启第二条 UI 定时抓取链。
  • 并发与限速：UI 不能直接写 today_records。定时/手动刷新合并，快照发布持锁但网络请求不持快照锁；API 共享实例的请求调度需串行保护限速时点，航司请求和 Web 查询也不能绕过 0.6 秒礼貌限速。
  • 告警一致性：复用 AlertManager 的规则和防御性副本；UI 以只读版本/快照更新计数，不消费共享 new_flag 去影响其他消费者；无需把所有来源强行置于一个跨模块大锁。
  • 日志与终端：全屏会话期间，后台日志进入有界会话记录或现有日志设施，不直接在全屏上 print；退出后恢复原输出策略。外部航司名/状态去除 ESC、控制字符，作为纯文本显示，禁止解释为终端控制码或框架标记。
  • 退出：所有退出路径进入 finally；先停止接收动作并恢复终端，再等待本会话资源结束；标准库在途 HTTP 不保证可立即中断，必须有有界请求超时、迟到结果丢弃和清理超时报告，不能声称线程已经停止。只关闭自己创建的 Web/Poller，不误关闭外部借入资源。

08迁移与兼容：可回退，但不永久养两套界面

推荐依赖政策：基础安装保持无必装第三方包；拟提供 .[tui] 可选安装组。Textual 的实际版本范围、Python 条件标记和测试依赖，必须经 G0 验证后再写入 pyproject。新 TUI 支持目标为 Python 3.11 / 3.13，不声称其框架最低要求就是 3.11。

性能预算（目标，不是当前结果）

  • 在记录 CPU/OS/Python/终端版本的参考机上，离线首屏目标 ≤ 1 秒；UI 操作到反馈 p95 ≤ 100 ms（搜索防抖时间单独计）；快照发布到可见目标 ≤ 500 ms。
  • 连续 30 分钟、1,000 行夹具与持续刷新后，无随刷新次数线性增长的 widget、线程或通知队列；用采样轨迹而非一句“内存稳定”作证。
  • 退出终端恢复目标 ≤ 2 秒；网络 worker 清理采用明确总预算，初拟 ≤ 20 秒，G0 验证现有 15 秒 HTTP 超时及排队后校准；超预算报告失败，不将 daemon 尚存当作已清理。
  • 只更新变化投影，不无条件每秒重建整张表；小型时钟/年龄标签可轻量更新。

  • Python 分层：新 TUI 3.11+，基础 CLI/Web/plain 继续 3.7+？推荐：接受，先做 G0 验证。

  • 降级策略：plain 保底而非功能对等；legacy 只用于迁移期？推荐：接受。

关键风险与明确放弃的能力
  • 框架与打包：运行时分层会增加组合测试；若发行依赖无法隔离则不能合入默认路径。
  • 真实终端：headless 通过不等于 Windows 输入法、颜色和快捷键通过；至少一次真人或真实终端记录不可省略。
  • 后台接口：刷新来源/时间并非已有事实，不能用 UI 猜测替代 API/Poller 元数据。
  • 源数据缺口：机场名称、预计时间、注册号不一定有结构化数据；只展示已提供字段，不生成看似合理的信息。
  • 兼容代价：放弃旧版“任意字符直接过滤”、simple 实时重绘幻想，以及 Python 3.7 上的完整新 UI；保留可用 CLI 与 plain。
  • 范围膨胀：时区统一、持久化和 Web 重写不随本次顺带推进；出现必须破坏契约的问题先回报，不用重构名义跨过审批。

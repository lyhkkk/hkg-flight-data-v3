三、新引入的问题（2 项 P1 + 2 项 P2）

V1. 两字母 + 1~2 位数字的航班号被误判为「停机位」→ 静默返回 0 条 P1

cli.py:36 _is_stand() · search_flights() 模式判定

_is_stand 的正则 [A-Z]{1,2}\d{1,2} 会命中所有「2 字母 + 1~2 位数字」的航班号，且判定优先级高于航班号匹配，没有任何兜底回退：

输入      stand   判定
CX75      True    停机位   ← 本应是航班号
BA15      True    停机位   ← 真实航班号
KA21      True    停机位   ← 真实航班号
HX22 / UO23 / SQ2 / JL26   全部误判
CX759     False   航班号   （3 位数字不受影响）

端到端复现（构造含 BA15 的数据源）：

query BA15 -> 0 条结果   # 航班实际存在，却被拿去比对 stand 字段
query W63  -> 1 条结果   # 停机位搜索本身正常

危害是静默的：用户查一个存在的航班，得到 0 结果，会以为航班不存在。

建议（三选一）：① 给停机位加前缀限定，只认 HKIA 实际机位前缀（W/N/R/S/E + 数字，如 [WNRSE]\d{1,3}）；② 保留宽松正则，但当停机位/登机门搜索返回 0 条时回退按航班号再搜一次并提示；③ 加显式标识，如 query stand:W63 / --stand W63，彻底消除歧义。

V2. 新增 curses 测试未做平台跳过，Windows 下测试套件报红 P1

test_hkg_flight.py:798-833 TestCursesTUI

两个新测试直接依赖 curses，而 Windows 的 CPython 没有 _curses 模块。在你自己的开发机上现在是这样：

$ python -m unittest test_hkg_flight
Ran 82 tests in 1.869s
FAILED (errors=2)
  ERROR: test_alert_and_airline_modes_render_their_views  ModuleNotFoundError: No module named '_curses'
  ERROR: test_printable_filter_and_escape                ModuleNotFoundError: No module named '_curses'

CI 跑在 ubuntu-latest，curses 存在，所以 CI 仍是绿的——但这意味着本地信号失真：上轮"58/58 全绿"的可信度被破坏了，而项目 README 本身就把 Windows + windows-curses 列为支持场景。

建议：给类加 @unittest.skipUnless(_curses_available(), "requires curses")（用 importlib.util.find_spec("_curses") 探测）。这样 Windows 显示 80 passed / 2 skipped，Linux 全量 82。

V3. --force 实际只作用于航司缓存 P2

api.py:23,87,104 · cli.py:588

bypass_cache 只在 fetch_airlines() 的两处读取分支生效；fetch_flights() 从头到尾不读缓存（缓存仅在 poller 里做降级兜底），所以 --force 对航班数据没有任何额外效果。帮助文本"Bypass cached data (fetch fresh from the API)"略有夸大。

建议：把帮助改成"Bypass cached airline data"；或让 Poller.refresh_today() 也尊重该标志，使其名副其实。

二、残留问题（2 项，均为 P3）

R1. 「单字母 + 数字」的输入仍被判为停机位 P3

cli.py:30 _is_stand() · cli.py:44 _is_airline_code()

收紧后的正则 [WNRSEDX]\d{1,3} 解决了「2 字母 + 数字」这一大类，但单字母 + 1 位数字仍会命中。而 IATA 航司代码恰好存在这种形态——D7 = AirAsia X（在 HKIA 有实际运营）：

输入    判定
D7      停机位   ← AirAsia X 的航司代码
X7/E3   停机位   ← 同类形态
CX75    航班号   ← 已修复
D7233   航班号   ← 正常

端到端：query D7 → 0 条（被拿去比对 stand 字段）；query D7233 → 1 条，正常。
根因是 _is_airline_code 只认 [A-Z]{2}，不认「字母+数字」形态的航司代码，于是这类输入既落不到航司、又被机位截胡。

建议（推荐第 ② 条，一次性解决所有歧义）：① 把 _is_airline_code 放宽为 [A-Z]\d|[A-Z]{2}，让 D7 走航司分支；② 更稳妥——加「0 结果回退」：当机位/登机门搜索命中 0 条时，自动按航班号再搜一次并打印提示（如「未找到机位 D7，已按航班号搜索」）。这样无论未来出现什么新的歧义形态都不会静默返回空。

R2. read_state / write_state 仍是零调用死代码 P3

cache.py:143-151（本轮未改动）

state.json 相关的一对方法全项目仅剩定义处 2 处引用，没有任何调用点，文档却仍把它列为缓存文件之一。建议连同 state_path 一并删除，或真正用起来做航班状态快照。

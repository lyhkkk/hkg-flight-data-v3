总体判断
功能骨架完整、标准库零依赖、缓存与限速设计思路是对的，但项目当前处于两版并存且已分叉的状态：包版本是从单文件版"拆出来"的，拆的过程中丢失了单文件版后来做的修复（Web UI 转义、暗色主题），同时引入了新的导出/渲染缺陷。测试套件当前 100% 无法运行，而 PROJECT-STATUS.md 记录"58 个测试全部通过"——这条记录是失效的。
阻断级问题
6 项 P0：测试不可运行、Web UI 存储型 XSS、路径穿越任意文件写、双实现分叉、curses TUI 按 W 崩溃、简单 TUI 告警/航司视图崩溃。
最大风险
Web 服务默认监听 0.0.0.0 且无任何鉴权，叠加 XSS 与路径穿越，等于把"读航班 + 往本机任意路径写 JSON"的接口暴露给局域网。

一、必须先修的 6 项（P0）

1. 测试套件根本跑不起来 P0 可维护性

test_hkg_flight.py:15-37 · hkg_flight/__init__.py:21-35

测试从包里导入 Poller、search_flights、flights_for_date、load_airlines，但 __init__.py 只导出了 CacheSystem / APIClient / AlertManager 和 utils 里的几个函数。结果是 import 阶段就失败，58 个测试一个都没执行。

$ python -m unittest test_hkg_flight

这也解释了为什么 PROJECT-STATUS.md 里"58 个测试全部通过"的结论没有被 CI 拦住——它从未真正验证过。

修复：在 __init__.py 补上 Poller、以及从 .cli 导出 search_flights / flights_for_date / load_airlines（注意 .cli 导入会带入 sys 副作用，更干净的做法是把这三个函数下沉到 utils.py 或新建 query.py，再由 cli 引用）。同时补一个 GitHub Actions 或 pre-commit，把测试真正跑起来。

2. 两套实现并存且已经分叉 P0 简洁 · 可维护性

hkg_flight.py（2 378 行，单文件）↔ hkg_flight/（8 个模块，约 2 400 行）

两份代码实现了同一套东西，但已经不是同一版本了：

维度单文件 hkg_flight.py包 hkg_flight/
Web UICSS 变量 + 完整暗色主题 + esc() 转义 + 状态色退化版：无转义、无主题变量、无空状态
API 契约{"date","count","flights":[...]} 包装结构直接返回裸数组

两份前端/后端互不兼容，改任何一处都要同步两遍，而同步已经失败了一次（见第 3 条 XSS）。

修复：二选一，立刻删掉另一份。建议保留包结构（可测试、可扩展），但把单文件版的 Web UI（含 esc() 与 CSS 变量）与包装式 API 契约移植回 web.py；然后统一 README/COMMANDS 为 python -m hkg_flight。

3. Web UI 存储型 XSS（包版本） P0 安全

hkg_flight/web.py:320-330

表格用模板字符串拼 innerHTML，插入的 flight_number / origin / destination / status 全部来自外部 HKIA API 的返回，没有任何转义。

tbody.innerHTML = flights.slice(0, 100).map(f => `
    <td><strong>${f.flight_number || 'N/A'}</strong></td>
    <td><span class="status status-${f.status_category}">${f.status}</span></td>
` ).join('');

只要 HKIA 接口返回（或链路被劫持返回）含 <img src=x onerror=...> 的字段，脚本就在访问者浏览器里执行。讽刺的是单文件版 hkg_flight.py:1289 已经写了 const esc=s=>String(s??'').replace(/[&<>"']/g,...)——拆分时把这个修复弄丢了。

修复：把单文件版的 esc() 搬过来，对所有插值调用；或改用 textContent / document.createElement 构建行。再加 Content-Security-Policy: default-src 'self' 响应头做纵深防御。

4. 路径穿越 → 任意文件写入 P0 安全

web.py:149,189 → api.py:66-69 → cache.py:44

/api/flights?date= 与 /api/search?date= 的查询参数未做任何校验就直接拼进缓存文件名：

cache.py:44
return os.path.join(self.cache_dir, "flights_{}.json".format(date_str))

实测：
date=2026-09-07      -> ~/.hkg_flight_cache/flights_2026-09-07.json
date=../../../evil   -> ~/.hkg_flight_cache/flights_../../../evil.json  # 逃出缓存目录

配合 write_flights 的 json.dump，攻击者可以在本机任意可写路径写 JSON 文件（内容部分可控：来自 API 响应）。同时该参数还被拼进上游 URL，存在查询参数注入。

修复：用正则白名单校验：if not re.fullmatch(r"\d{4}-\d{2}-\d{2}", date_str): return 400；写入前再用 os.path.abspath(path).startswith(abspath(cache_dir)) 断言一次。URL 拼接改用 urllib.parse.urlencode。

5. curses TUI 按 W 直接崩溃 P0 实用

hkg_flight/tui.py:545
elif ch.lower() == ord("w"):
    self.cmd_web()

getch() 返回的是 int，int 没有 .lower()。用户按下 W（README 里宣传的"启动/停止 Web 服务"）会抛 AttributeError，而 run() 循环没有 try/except，异常直接穿出 curses.wrapper，整个 TUI 挂掉、终端状态残留。

修复：elif ch in (ord('w'), ord('W')):。同时给 handle_key 加兜底 except Exception: log(...)，别让一个按键杀死整个界面。

6. 简单 TUI 的告警/航司视图必崩 P0 实用

hkg_flight/tui.py:122-131

render() 里 flights 只在 else 分支赋值，但分支结束后无条件使用它。按 5（告警）或 6（航司）→ UnboundLocalError。

if mode == "alerts":   ...   # 不定义 flights
elif mode == "airlines": ... # 不定义 flights
else:  flights = get_flights()
pages = max(1, (len(flights) + 19) // 20)   # ← 崩溃点
修复：在 alerts / airlines 分支末尾 return。

二、安全（Security）

7. Web 服务默认绑定 0.0.0.0 且无鉴权 P1

hkg_flight/web.py:39
self._server = ThreadingHTTPServer(("", self.port), handler)

空 host = 监听所有网卡。README 写的是 "localhost:8080"，实际会暴露到整个局域网/公网（若在云服务器上运行）。没有 token、没有 Basic Auth、没有 IP 白名单，任何人都能读 /api/* 并利用上面的穿越写文件。

修复：默认改为 ("127.0.0.1", port)，需要对外时通过 --host 显式开启并强制要求设置访问 token。

8. CORS 全开 Access-Control-Allow-Origin: * P1

web.py:79, 121

所有 JSON 响应和 SSE 都带 *。任意第三方页面都能用受害者浏览器读取本机 8080 端口的航班数据（配合上面的 XSS 可形成完整攻击链）。本地服务没必要开 CORS。

修复：删除该头；若确实需要前端跨域，限制为 http://127.0.0.1:PORT。

9. --force + --cache-dir 可递归删除任意目录 P1 危险脚枪

cli.py:157-163（clear_cache）· cli.py:402-405（--force 触发）· cli.py:284-288（clear-cache 命令）
if os.path.exists(cache_dir):
    shutil.rmtree(cache_dir)      # 无路径合法性校验

--cache-dir 是用户可控的，--force 会无条件调用 clear_cache(cache)。一旦误传 .、~ 或某个项目路径，就是一次不可恢复的 rmtree。

修复：(a) 拒绝删除非缓存目录：校验 basename(cache_dir) == ".hkg_flight_cache" 或要求 --yes 二次确认；(b) 改用"逐文件删除"而非 rmtree；(c) --force 语义改为"本次请求绕过缓存"，而不是"删光缓存"。

10. 单文件版存在无效转义序列 P2 前瞻性

hkg_flight.py:1312
esc(f.origin||'--').replace(/\|/g,'/')   # 在普通字符串中，\| 是无效转义
Python 3.12+ 报 SyntaxWarning，未来版本将升级为 SyntaxError
修复：把含正则的 HTML 模板字符串改为 raw string：r"""..."""。

其他安全观察（低优先级但建议一并处理）

  • 访问日志被静默吞掉（web.py:69-71 log_message 直接 pass）——出事后无法审计谁访问过。至少保留到 stderr 或文件。
  • os.system("cls"/"clear")（tui.py:60）——虽然参数是常量不构成注入，但会拉起 shell 进程；改用 print("\033[2J\033[H") 或 subprocess。
  • 无请求超时/体量限制：BaseHTTPRequestHandler 未设置 timeout；SSE 连接永久占用线程（ThreadingHTTPServer 每连接一线程，多开几个标签页即可耗尽）。建议给 SSE 设上限与空闲超时。
  • 无 TLS、无安全响应头（CSP / X-Content-Type-Options / Referrer-Policy 全缺）。
  • _clients 列表无锁（web.py:29,125,142）：多线程 append/remove 存在竞态，改用 threading.Lock 或 set+锁。

三、实用（Utility）

11. --port / --cache-dir 的参数值没被消费 P1

cli.py:395
args = [a for a in argv if a not in ("--web", "--no-poll", "--force", "--port", "--cache-dir")]

只移除了 flag 本身，没移除它后面的值。实测：['--web','--port','9000'] → 残留位置参数 ['9000'] → 被当成子命令 → 打印 usage 并返回 1。

后果：python -m hkg_flight --web --port 9000 完全无法使用，而 README 和 COMMANDS.md 第一条就是这个用法。--cache-dir 同理。

修复：丢掉手写解析，改用 argparse（带子命令 query/departures/arrivals/alerts/clear-cache）。这是本项目性价比最高的一次重构——顺带解决下面第 12 条的 --help 问题。

12. curses TUI 的告警 / 航司视图是空白的 P1

tui.py:306-348 · tui.py:440-467

render() 无条件调用 _render_flights()，从不按 self.mode 分发。_render_alerts() 和 _render_airlines() 写好了但从未被调用。而 visible_flights() 对 mode=="alerts" 返回空列表，所以按 5/6 只会看到 "No flights found."。

修复：render() 里按 mode 分发到三个 _render_*。

13. curses 模式下无法输入过滤文本 P1

tui.py:527-570 · README.md:80

README 承诺"Type any text 过滤航班号/航线"，但 handle_key 里没有任何分支把可打印字符追加到 filter_text。过滤功能在 curses 版中完全不存在（只有简单 TUI 版有，且实现是把整个 dict 转字符串再匹配，输入 "gate" 会命中所有行）。

修复：在 handle_key 末尾加 elif 32 <= ch < 127: self.filter_text += chr(ch)，并处理 KEY_BACKSPACE。

14. Web 服务关闭后端口不释放 P1

web.py:48-53
self._server.shutdown()      # 只停 serve_forever 循环
self._server = None          # 缺少 server_close()，监听 socket 未关闭

TUI 里按 W 关闭再开启会撞上 Address already in use（在 Windows 上尤其明显）。

修复：shutdown() 后紧跟 server_close()。

19. CLI 表格长内容会顶坏对齐 P2

cli.py:195-211
print("{:<6} {:<10} {:<6} {:<20} {:<18} {:<12} {:<5}".format(...))

格式串只设最小宽度、不做截断。多航段航线（如 HKG -> SIN|BKK）或长状态文本超过 20 列时，会把后面所有列整体推右，表格错位。中文/emoji（如 ⚠）宽度按 1 计算，同样会错位。

修复：统一 truncate(s, n) 辅助函数（并按显示宽度 unicodedata.east_asian_width 计算），所有列先截断再格式化。

美观细节建议

  • 无颜色开关：CLI/TUI 无条件输出 ANSI 转义，重定向到文件或管道给 grep 时会出现乱码。应检测 sys.stdout.isatty()，并提供 --no-color 与 NO_COLOR 环境变量支持。
  • 排版风格不统一：CLI 详情用 --- Flight #1 --- 分隔、表格用 — 连接标题、告警用 ⚠+→。建议统一为一套符号体系。
  • TUI 列宽固定（6/10/6/20/18/12/5 = 80 字符），窄终端下直接截断；应随 getmaxyx() 动态分配比例。
  • Web UI 无排序：默认按 API 返回顺序，未按时间排序，对"航班看板"这个核心场景不友好。
  • 提示噪音：cmd_query 无论是否命中都会打印 "Tip: Use --codeshare..."。
